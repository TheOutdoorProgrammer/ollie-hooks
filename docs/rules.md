# Rules

Generated by `ollie-hooks docs`. Do not hand-edit.

Every rule ships disabled. Enable one in `~/.config/ollie-hooks/config.toml`:

```toml
[rules.<id>]
enabled = true
```

## no-codegen

Block writes to trees configured as off-limits to AI-authored code.

Ships protecting nothing: the projects that refuse AI-authored code are yours to name, and a shipped default would be guesswork about someone else's policy.
Matching is a plain substring against the normalised absolute path, so `match = "opentofu"` also blocks a sibling directory merely named `not-opentofu-notes`.

## secret-scan

Scan the prompt for credentials and block before it is sent.

UserPromptSubmit is the only event that can stop text before it reaches the API, so this is the last point a pasted credential can still be caught — PreToolUse is already too late, and a commit-time gate never sees chat at all.
Findings name the kind and line, never the value: repeating a secret into the block reason would put it straight back into the transcript this rule exists to keep it out of.

## secret-redact

Replace credentials in tool output with a placeholder before Claude reads it.

Once a secret reaches Claude's context it is in the transcript for good, and nothing downstream can take it back.
Matches on the literal value rather than reported column offsets, because column arithmetic breaks on multibyte output and a partial redaction is worse than none — it looks like it worked.

## lint

After an edit, run the file's linter and report what it found (never blocks the edit).

Dispatches by file extension to whichever of about ten linters fits, which is why the set is configurable: all-or-nothing enabling would demand every one of those tools from every user.
Leaving `linters` empty runs whatever happens to be installed; naming one is a commitment, so a named linter that is missing gets reported instead of quietly skipped.
A package-scoped linter's findings are narrowed to the edited file, so sibling-file noise never reaches the model.

| `linters` | `[]` | linters to run, by command name; empty means whatever is installed, and a named one that is missing is reported |

## comments

Flag verbose or agent-memo comments a change touched (advisory) — justify, slim, or remove.

Scans only the comments an edit introduced or modified, so a file full of pre-existing prose never fires until you touch it.
BDD markers, linter directives, shebangs and package doc comments are exempt.

## bash-output

Re-print a collapsed Bash result in full, so it needs no ctrl+o.

Claude Code collapses long Bash output behind ctrl+o; this prints it in full on screen instead.
Display-only, so the transcript and the model's own context keep the original either way.

## mermaid-stream

Render mermaid fences as terminal ASCII, inline while text streams.

Renders as the message streams, so a diagram appears inline rather than after the fact.
Needs Claude Code's `verbose` setting OFF — verbose shows the original text, which makes this rule look broken.
Only `graph`/`flowchart`, `sequenceDiagram` and `erDiagram` parse; anything else, or anything wider than `width_cap`, keeps its fence unchanged.

## prose-wrap

Flag markdown prose a change hard-wrapped mid-sentence (advisory) — one sentence per line.

One sentence per line keeps a diff to the sentence that changed; hard wrapping reflows every following line and buries the actual edit.
Only lines a change actually touched are flagged, and code blocks and tables are never prose.
